# Bar Order Bot MVP

Рабочий MVP Telegram-бота для бесплатного заказа напитков на небольших мероприятиях.

Сейчас реализован сквозной сценарий:

1. Гость открывает Telegram-бота и сразу попадает к официанту.
2. Пишет или диктует пожелания либо выбирает позиции в Telegram Mini App.
3. Отправляет корзину и получает номер заказа.
4. Заказ появляется в браузерной панели бармена.
5. Статусы заказа меняются по таймеру; бармен при необходимости меняет их вручную.
6. Гость получает Telegram-уведомление о готовности.

Дополнительно доступны «Ваш официант» на базе Gemini через OpenRouter, текстовый
и голосовой заказ на русском и английском, рекомендации по вкусу, крепости и
настроению, контекстный диалог и исправление черновика заказа обычной фразой,
редактирование отправленного заказа до принятия барменом, стоп-лист, пауза
приёма заказов, управление мероприятиями и операционная аналитика.
Mini App показывает всё доступное меню, общую с ботом корзину, случайную
позицию «Мистери» и топ-10 гостей за мероприятие. Заказ отправляется только
после явного подтверждения.

Demo-каталог содержит 30 популярных позиций: 20 напитков и 10 блюд. Повторный
запуск seed добавляет отсутствующие demo-позиции, но не удаляет созданное
администратором меню.

Главный экран содержит три кнопки: «Открыть заказ», «Открыть меню» и
«Дайте мне рекомендацию». Официант принимает текст и голосовые без включения
отдельного режима. Кнопка заказа показывает неподтверждённый черновик, корзину
или статус уже отправленного заказа. Если корзина и отправленный заказ
существуют одновременно, в корзине доступна ссылка на его статус.
История разговора сохраняется при переходах по меню в текущем сеансе бота.
При первом запуске язык выбирается по Telegram (русский или английский);
изменить его можно командой `/language`.

## Технологии

- Python 3.12+
- FastAPI
- aiogram 3
- PostgreSQL в production
- SQLAlchemy 2
- Alembic для миграций схемы
- Jinja2 + JavaScript для служебных панелей
- React + TypeScript + Vite для Telegram Mini App
- RapidFuzz для сопоставления свободного текста с меню
- Docker Compose

SQLite используется только как удобный локальный режим. В Docker Compose приложение работает с PostgreSQL.

## Быстрый локальный запуск

```powershell
cd bar-order-bot
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
alembic upgrade head
uvicorn app.main:app --reload
```

После запуска:

- API и документация: `http://127.0.0.1:8000/docs`
- панель бармена: `http://127.0.0.1:8000/staff`
- панель администратора: `http://127.0.0.1:8000/admin`
- панель владельца/аналитика: `http://127.0.0.1:8000/owner`
- проверка сервиса: `http://127.0.0.1:8000/health`
- Mini App: `http://127.0.0.1:8000/miniapp` после `npm ci` и `npm run build` в `miniapp/`

При `SEED_DEMO=true` автоматически создаются активное demo-мероприятие и несколько напитков.
В обычном браузере Mini App покажет экран входа: реальные заказы доступны
только при открытии из Telegram с подписанными `initData`.

## Telegram Mini App

1. В `.env` заполните `BOT_TOKEN` и `LEADERBOARD_PSEUDONYM_SECRET` (случайная
   строка минимум 32 байта). Для локальной разработки без публичного URL
   `MINI_APP_BASE_URL` оставьте пустым: бот сохранит прежнее кнопочное меню.
2. Для проверки на телефоне обеспечьте публичный HTTPS-адрес, ведущий к FastAPI.
   В `MINI_APP_BASE_URL` укажите только origin, например
   `https://bar-test.example.org`, без `/miniapp`. URL должен быть устойчивым
   на всё время мероприятия. `WEBHOOK_BASE_URL` можно оставить пустым, если
   бот работает в polling-режиме.
3. Запустите или пересоберите контейнеры:

```powershell
docker compose --profile telegram up -d --build
docker compose ps
```

4. Откройте в личном чате `/start` и нажмите новую кнопку «Открыть меню».
   В старых сообщениях callback-кнопки меню продолжают работать. Если кнопка
   всё ещё открывает чат-каталог, проверьте HTTPS URL в `.env` и перезапуск
   контейнера `bot`.
5. Добавьте позицию, подтвердите заказ и проверьте его в `/staff`.

FastAPI обслуживает Mini App по `/miniapp` и API по `/api/v1/miniapp/*`.
После завершения заказа гость может нажать «Повторить предыдущий заказ» в меню
или на экране заказа. Позиции, добавки и комментарии копируются в корзину для
проверки перед отправкой. Если корзина уже заполнена, приложение сначала
предупредит о замене. Повтор доступен в рамках того же мероприятия, пока приём
заказов открыт и нет активного заказа; недоступные позиции не копируются.
Frontend собирается автоматически при `docker compose ... --build`; при
локальном запуске из VS Code сначала запустите PostgreSQL (`docker compose up -d db`)
и укажите в локальном `.env` адрес БД с хостом `127.0.0.1` вместо Docker-хоста
`db`. Затем выполните:

```powershell
cd miniapp
npm ci
npm run build
cd ..
alembic upgrade head
uvicorn app.main:app --reload
```

В профиле Mini App показываются ачивки текущего вечера. «Первый контакт»
выдаётся за первый заказ через любой канал, «Следопыт» — за спрятанный знак
на экране «Мистери», «Знаток» — за верный ответ в викторине. Значки хранятся
по мероприятию и гостю; повторное действие не создаёт дубликат.

Секретное меню настраивается во вкладке «Секретное меню» панели администратора:
выберите позицию и мероприятие, задайте загадку, ответ, интервал и количество
порций. Гость увидит напиток после верного ответа. Порция резервируется при
подтверждении заказа; при отмене до начала приготовления она возвращается в
остаток. Создание секретного предложения скрывает позицию из обычного меню
только на выбранном мероприятии.

Если проверяете через туннель, **не публикуйте** тестовые ключи панелей и
Adminer. Ограничьте внешние маршруты до `/miniapp`, `/miniapp/assets/*`,
`/api/v1/miniapp/*` и двух нужных статических ассетов, либо защитите панели
отдельным сетевым доступом. При заполненном `MINI_APP_BASE_URL` старые
гостевые REST-маршруты `/api/v1/users*` и `/api/v1/orders*` отвечают `410`:
они принимали произвольный Telegram ID и небезопасны для публичного сервера.
Бот ими не пользуется и продолжит работать. Адрес `127.0.0.1` сам по себе
не подходит для открытия Mini App на телефоне внутри Telegram.

## Telegram в режиме polling

1. Создайте бота через BotFather.
2. Укажите `BOT_TOKEN` в `.env`.
3. Один раз примените миграции:

```powershell
alembic upgrade head
```

4. В одном терминале запустите API:

```powershell
uvicorn app.main:app --reload
```

5. Во втором терминале запустите получение Telegram-сообщений:

```powershell
python -m app.bot.runner
```

Для production polling не требуется. Укажите публичный HTTPS-адрес в `WEBHOOK_BASE_URL`, после чего FastAPI установит webhook при старте.

## Полный тестовый запуск с PostgreSQL

Для тестового стенда достаточно Docker Desktop. Текущий `.env` уже настроен на
PostgreSQL внутри Docker, поэтому API и база запускаются одной командой:

Для production и нескольких процессов API используйте PostgreSQL. SQLite
подходит для локального запуска с одним процессом: замена уведомлений о статусе
при SQLite сериализуется внутри процесса приложения.

```powershell
cd C:\Users\user\Documents\ChatGPT\ML\bar-order-bot
docker compose --profile tools --profile telegram up -d --build
```

Проверить состояние сервисов:

```powershell
docker compose ps
docker compose logs -f app
```

После запуска доступны:

- Swagger API: `http://127.0.0.1:8000/docs`
- панель бармена: `http://127.0.0.1:8000/staff`
- панель администратора: `http://127.0.0.1:8000/admin`
- панель владельца: `http://127.0.0.1:8000/owner`
- health-check: `http://127.0.0.1:8000/health`
- Adminer: `http://127.0.0.1:8080`
- PostgreSQL: `127.0.0.1:5432`

Профиль `telegram` запускает бота в polling-режиме, а профиль `tools` — Adminer.
Если Telegram пока не нужен, API и PostgreSQL запускаются командой
`docker compose up -d --build`.

При старте контейнер `app` автоматически выполняет `alembic upgrade head`, а
затем запускает FastAPI. Существующий Docker volume PostgreSQL сохраняется.

### Просмотр PostgreSQL через браузер

Adminer запускается отдельным необязательным профилем:

```powershell
docker compose --profile tools up -d adminer
```

Откройте `http://127.0.0.1:8080` и используйте параметры:

- система: `PostgreSQL`
- сервер: `db`
- пользователь: `barbot`
- пароль: `значение POSTGRES_PASSWORD из .env`
- база данных: `barbot`

### Подключение настоящего Telegram-бота

Создайте бота через BotFather и локально вставьте полученный токен в
`BOT_TOKEN` файла `.env`. Не отправляйте токен в чат и не добавляйте `.env` в
Git. Затем запустите Telegram polling:

```powershell
docker compose --profile telegram up -d bot
docker compose logs -f bot
```

Публичный адрес и webhook для локального теста не нужны: бот получает сообщения
через polling. Если изменить `.env`, пересоздайте нужный контейнер:

```powershell
docker compose --profile telegram up -d --force-recreate bot
```

Если менялся Python-код, шаблоны или зависимости, пересоберите весь стенд:

```powershell
docker compose --profile tools --profile telegram up -d --build --force-recreate
```

### Остановка и повторный запуск

```powershell
docker compose stop
docker compose start
```

Обычный `docker compose down` удаляет контейнеры, но сохраняет данные в Docker
volume. Команда `docker compose down -v` также удалит тестовую базу целиком —
используйте её только когда действительно нужен чистый стенд.

Значения `local-*-2026` и пароль базы предназначены только для локального
тестирования. Перед публикацией их необходимо заменить.

## Голосовой заказ

Голосовой сценарий работает через OpenAI-совместимый multipart API. Для
OpenRouter укажите ключ, базовый адрес и модель (имя `OPENAI_API_KEY` сохранено
для обратной совместимости, в этой переменной может находиться ключ OpenRouter):

```text
OPENAI_API_KEY=sk-or-v1-...
OPENAI_BASE_URL=https://openrouter.ai/api/v1
OPENAI_TRANSCRIPTION_MODEL=openai/whisper-large-v3-turbo

ASSISTANT_ENABLED=true
ASSISTANT_API_KEY=
ASSISTANT_BASE_URL=https://openrouter.ai/api/v1
ASSISTANT_MODEL=google/gemini-3.1-flash-lite
```

Если `ASSISTANT_API_KEY` пуст, «Ваш официант» использует ключ из
`OPENAI_API_KEY`. Модель не добавляет позиции напрямую: сервер проверяет ID
напитков и модификаторов по доступному меню, после чего гость обязательно
подтверждает результат. При ошибке OpenRouter автоматически используются
локальный парсер RapidFuzz и локальный алгоритм рекомендаций.

Официант получает последние реплики диалога, текущую корзину и неподтверждённый
черновик. Поэтому он может понимать контекстные фразы вроде «ещё такой же»,
«второй без льда» или «замени его на что-нибудь кислое». При неоднозначности он
задаёт один уточняющий вопрос; корзина изменяется только после подтверждения
гостем. После подтверждения бот отправляет весь пересказанный заказ бармену.

Для напитка вне меню бот пытается найти базовый рецепт в TheCocktailDB и
показывает гостю ингредиенты, способ приготовления и ссылку на источник.
Пожелания гостя сохраняются вместе с рецептом в очереди бармена: бармен
проверяет наличие ингредиентов и решает, какие изменения возможны. При ошибке
поиска исходный запрос всё равно передаётся бармену. Для локальной разработки
можно задать `COCKTAIL_DB_API_KEY=1` в своём `.env`; для production нужен
собственный ключ согласно [условиям API](https://www.thecocktaildb.com/api.php).

Не добавляйте настоящий ключ в `.env.example` и не коммитьте файл `.env`.
После изменения настроек пересоздайте контейнер бота:

```powershell
docker compose --profile telegram up -d --force-recreate bot
docker compose logs -f bot
```

Для прямого подключения к OpenAI оставьте
`OPENAI_BASE_URL=https://api.openai.com/v1` и выберите поддерживаемую OpenAI
модель, например `gpt-4o-mini-transcribe`.

Если ключ не задан или сервис недоступен, бот предлагает использовать текстовый заказ или каталог. Основной сценарий не блокируется.

## Панель бармена

Панель обновляется каждые 2,5 секунды. В ней доступны:

- звуковое уведомление о новом заказе, включаемое вручную;
- фильтры по активным статусам;
- предупреждение после 5 минут и критическая отметка после 10 минут;
- optimistic locking: если два сотрудника одновременно меняют заказ, второй
  получает сообщение и свежую очередь;
- отдельная обработка запросов на позиции вне меню.
- подсказка приготовить одинаковые напитки сразу для нескольких заказов:
  группируются только совпадающие позиции, добавки, комментарии к позиции и заказу;
- время следующего автоматического перехода на каждой карточке заказа.

Пороговые значения меняются через `STAFF_WARNING_MINUTES` и
`STAFF_CRITICAL_MINUTES` в `.env`.

Автоматические переходы включены по умолчанию (`AUTO_PROGRESS_ENABLED=true`).
Интервал проверки задаётся `AUTO_PROGRESS_POLL_SECONDS` (по умолчанию 10 секунд).
Время этапа рассчитывается при поступлении заказа или переходе на новый этап:
чем больше активных заказов в этот момент, тем длиннее ожидание. Для 3 заказов
оно короче, чем для 25; при приготовлении учитывается также число порций.
Бармен может менять статус сразу, без ожидания таймера. На карточке заказа
полоска показывает остаток времени до следующего автоматического перехода.
На этапе приготовления полоска показывает ориентир, а статус «Готов» всегда
подтверждает бармен вручную. После этапа «Готов» заказ закрывается таймером,
но остаётся в
панели в разделе проверки выдачи, пока бармен её не подтвердит. Гость получает
сообщение о закрытии по таймеру. Аналитика считает подтверждённую выдачу и
закрытие по таймеру отдельно. У старых активных заказов
таймер запускается с момента первого прохода фоновой проверки.

## Нагрузочная проверка

После запуска стенда выполните read-only тест на 300 запросов:

```powershell
python scripts/load_test.py --requests 300 --concurrency 30
```

Скрипт не создаёт пользователей и заказов: он проверяет `/health` и выдачу
меню, затем показывает число ошибок, RPS и задержки p50/p95/p99.

### Роли тестового стенда

- `STAFF_TOKEN` — очередь заказов и смена статусов;
- `ADMIN_TOKEN` — меню, модификаторы, мероприятия, стоп-лист и пауза заказов;
- `OWNER_TOKEN` — просмотр аналитики и экспорт;
- `ANALYST_TOKEN` — тот же read-only доступ к аналитике без административных прав.

В MVP это общие токены команды, а не отдельные учётные записи. Панели не
показывают цены: на мероприятии напитки выдаются бесплатно.

## Что ещё нужно перед публичным размещением

- настроить production-домен и HTTPS;
- заменить demo-токены;
- заполнить реальное меню и псевдонимы;
- провести нагрузочный и полевой тест в помещении бара;
- добавить подтверждение изменения уже принятого заказа;
- настроить резервное копирование PostgreSQL и внешний мониторинг ошибок.

Mini App проверяет подпись Telegram `initData` на сервере. Старые гостевые
маршруты с произвольным `telegram_id` остаются только для закрытого локального
стенда и отключаются при указании `MINI_APP_BASE_URL`. Служебные панели нельзя
выставлять в интернет с тестовыми общими токенами.
